# 边际信息登记（EDGE LOG）

最后更新：2026-08-11

定位：情报层 → 策略层的结构化"为什么买"记录。与任务 6 情报库的赛前情报层结合
（预期情形 / 事件情报 / 队伍画像），作为**后台统计**输入；前台只展示结论性情报，不裸展示逐笔明细。

## 为什么需要

```text
现有信号全部来自价格序列；08-05 九连负 vs 08-06 晚间 +700 的差别在"边际信息"
（假赛感 / 比赛阅读 / 状态判断），不在形态。
登记后可以统计：有信息差 vs 纯信心的胜率 / 期望差异（"假赛感值多少钱"），
给 D5 信心溢价定仓、方向过滤是否启用提供数据依据。
```

## 字段（每笔交易登记一条）

```text
日期 / 比赛 slug / 市场层（game1 / game2 / moneyline）/ 方向 /
信息差类型 / 来源 / 时效（赛前 / 盘中）/ 价格位置 /
仓位处理（按 D5 规则：彩票仓上限 %）/ 结果（盈亏，估值标注）/
复盘链接
```

## 信息差类型词表

```text
match_read    比赛阅读（假赛感 / 送人头 / 节奏与团战判断）
lineup_bp     阵容与 BP
form_schedule 状态与赛程密度（连胜连败、背靠背）
event         事件情报（内讧 / 人员更换 / 教练变动）
caster        解说信号（虎牙解说 / 朋友聊天记录）
danmu         直播弹幕（观众信号，置信度低于解说，观察登记）
conviction    纯信心（无边际信息，D5 场景，登记作对照）
other         其他
```

信息差观察登记（2026-08-11 K杯 DNS vs HLE）：

```text
阵容公布（HLE 二队 vs DNS 一队）-> DNS 18.5c -> 66.5c 一分钟（约 3 倍）。
杯赛开赛前核对首发/阵容构成是确定性事件——赛前情报层固定检查项，
可提前小仓埋伏"信息差标的"；信息不明时仅小仓试注（信息不确定 = 价格不确定）。
```

## 统计口径（后台，不上前台）

```text
分组：有信息差 vs 纯信心（conviction）；按信息差类型细分。
指标：笔数 / 胜率 / 平均盈亏 / 期望。
用途：D5 仓位上限（信息差类型 → 可放大的仓位倍数）、方向过滤是否启用、
      形态路由的叠加权重（如 match_read 确认 + A1 形态 → 彩票机器可开）。
```
