# 主观情报库建设方案（主播/解说/弹幕信号 -> 结构化情报）

日期：2026-08-08

定位：赛前/赛中的"主观情报层"，与盘中形态（客观层）互补。
原则：情报只作边际信息（叠加方向偏好与仓位上限），不改变止损/止盈纪律（D5 规则）。

## 1. 数据源与可信度分层

说明：职业解说本身就是主播，不按"解说 vs 主播"分；按**路别**分：
一路（官方解说，合规保守）vs 二路（co-stream / 二路解说，多为职业选手转型，
敢说真话、技术细节多）。**二路解说是更高价值的信息源，采集首选。**

| 来源 | 例子 | 可信度 | 采集方式 |
| --- | --- | --- | --- |
| 二路解说（职业背景） | "HLE 主要靠上单发挥"、"某队中单不会玩所选英雄" | 高（首选） | 手动/语音转录 |
| 官方一路解说 | 官方主舞台解说（信息合规但偏保守） | 中高 | 手动/语音转录 |
| 官方/社区 | 公告、阵容、BP 信息 | 中 | 手动/API |
| 弹幕 | 高频关键词、情绪 | 低（需聚合） | 抓取+聚合过滤 |

## 2. 信号分类（标签体系）

```text
- 风格/打法：队伍靠谁赢（HLE 上单核心）、节奏从哪来（WE 打野核心）
- 状态：近期低迷/火热（HLE 持续低迷）、选手状态
- 熟练度：中单不会玩所选英雄（08-08 WB/LNG）
- BP/阵容：BP 意外、阵容克制
- 节奏/比赛阅读：领先会不会送、翻盘工具（BRO 英雄翻盘能力）
- 事件/风险：假赛怀疑、心态崩
```

每个信号 -> "预期情形"（赛前假说）-> 可映射形态库（如"上单核心被压制"-> 倾向 B4 阴跌；
"下狗有翻盘工具"-> 倾向 A1/A2）。

## 3. 结构化字段（扩展 INTEL_SIGNALS.md）

```text
日期 / 比赛 / 来源人 / 来源类型（职业解说/主播/官方/弹幕）/ 可信度 /
原话摘录 / 信号标签（风格/状态/熟练度/BP/节奏/风险）/ 对象（队伍/选手）/
方向含义（利好哪侧）/ 采集时间（赛前/赛中+比赛分钟）/
市场验证（采集前后价差）/ 赛后应验（是/否/待验证）
```

## 4. 采集流程（手动 -> 半自动 -> 自动）

```text
阶段 1 手动：每场比赛把听到的关键信号按模板录入（已开始：INTEL_SIGNALS.md）。
阶段 2 半自动：语音转录（主播/解说 -> 文字）+ 关键词标签辅助分类。
阶段 3 自动（未来）：弹幕抓取聚合（关键词频次/情绪）+ NLP 分类 + 可信度加权。
```

弹幕主观情绪分析（2026-08-08 用例确认）：用于"假赛/剧本/真状态差"三分类——
当单局赔率出现"干净翻转"（如 LEC SK/NAVI G2：领先 69.5c -> 22 分钟 0.05c）时，
采集弹幕中"假/演/剧本/明眼"类关键词频次 + 情绪波动 + 主播语气，
输出"疑似假赛"置信度，作为是否参与该形态的过滤信号。

## 5. 验证闭环

```text
信号 -> 采集前后市场价差 -> 赛后是否应验 -> 按"来源类型 x 信号标签"累计可信度
-> 高可信信号沉淀为队伍画像/预期情形（TEAM_PROFILES / 情报卡）。
样本目标：每组 >=15-20 条才出统计结论（先登记、不提前下结论）。
```

## 10. 规划层补充：技术点与盲点（2026-08-08 会话确认）

### 10.1 时间对齐（最容易漏、最影响验证的核心点）

```text
信号记录必须能映射到三个时间轴：
  流时间（直播/录播里说话的 offset）
  比赛时间（第几局第几分钟）
  市场时间（Polymarket 价格快照 UTC）
采集时同时记：流偏移分钟 + 比赛分钟 + UTC 时间；验证"采集前后价差"时用 UTC 对齐
市场快照，否则信号与价格对不上。
落地：timing 字段含 phase / minute / stream_offset_min；录入以比赛分钟为主，流偏移可选。
```

### 10.2 语音源获取：直播录制优先于事后录播

```text
虎牙录播可能被删或会员限制；直播时用 yt-dlp / streamlink 直接录最稳
（audio-only 即可，一场 2-4 小时约几百 MB）。yt-dlp 有虎牙 live extractor，
已知偶发"只录第一段"问题需实测验证；streamlink + ffmpeg 是备选。
录制同时可抓弹幕，时间戳天然对齐（10.8）。
```

### 10.3 转录方案分层：两条路 + 术语修正

```text
快速路（零部署）：通义听悟（每天约 2 小时免费、中文、可区分发言人）或飞书妙记（免费）。
私有批量路（长期）：本地 faster-whisper / whisper.cpp（large-v3-turbo），整场转录。
关键坑：电竞术语（英雄名、选手 ID、大核/翻盘/节奏）识别常错；转录后需用术语词典
做一次替换/校对，再进信号提取。
发言人归属：Whisper 无 speaker diarization；按解说分人统计需 pyannote 或云工具
（通义听悟支持）。短期先记"二路解说多人"，不细究是谁。
```

### 10.4 关键窗口转录（控制成本）

```text
整场转录成本高（长录音 + 大模型慢）。更优：realtime whisper + 关键词列表
（翻盘/不会玩/换人/状态/送/假赛）打标，只对命中窗口做精转写和人工标注。
这是阶段 2 的推荐形态，先于"整场转录 + 后处理"。
```

### 10.5 信号去重、冲突与共识

```text
同一观点多人说：合并为一条信号，related_signal_ids 记录共识，不重复入库。
相反观点并存：各自入库、不折叠；统计阶段看"方向一致性"。
对外（情报卡）展示"今日信号"以去重后信号为准，冲突时并列展示双方。
```

### 10.6 信号时效分层（画像会过期）

```text
durable（风格/打法、BP 规律）：进 TEAM_PROFILES 长期画像（如 HLE 上单核心）。
short_lived（状态、连败、低迷）：只进近期状态，有效期约 1-2 周，过期自动降权。
落地：每条信号加 timeframe 字段；TEAM_PROFILES 存 durable，
EXPECTATION_VERIFICATION 存 short_lived 的验证。
```

### 10.7 验证闭环的数据依赖

```text
"采集前后价差"依赖两个数据：
  1. 信号时刻附近的 Polymarket 快照（复用 fetch_price_snapshot / 盘中 1 分钟流）。
  2. 赛后结算结果（已有复盘流程）。
缺口：现有信号多为赛中补记、无采集前价；回填时标注"采集前价缺失"，不假装完整。
```

### 10.8 弹幕抓取：技术选型与合规

```text
技术：虎牙弹幕走 WebSocket 自定义二进制协议 + 加密，逆向维护成本高；候选：
  - ordinaryroad-barrage-fly（Java，虎牙/B站/斗鱼/抖音/快手，转发过滤平台）
  - passerby-b/douyin_danmu（Playwright 浏览器自动化 + JS 注入取解密后弹幕）
  - wbt5/real-url（真实流地址 + 弹幕，58 平台）
  - Gitee BarrageGrab（wss 直连多平台）
推荐：浏览器自动化路线（协议变更影响小）或 barrage-fly；先小规模验证单一直播间。
合规：弹幕是公开 UGC，但批量抓取可能违反平台服务条款。边界：个人研究使用、
低频采集、不对外转售/转载弹幕数据；对外只展示聚合结论（关键词频次/情绪），
不展示原始弹幕流。
```

### 10.9 对外发布边界（订阅制网站）

```text
网站只能展示：短摘录（一句）+ 来源人/来源类型 + 采集时间 + 可信度 + 应验统计；
不得发布完整转录稿、录音文件或大段原文（版权 + 平台用户协议）。
假赛/事件类只给信号 + 依据 + 来源，不断言（TASK6 红线 2）。
```

## 11. 画像情报库框架（解说内容 -> 三层画像）

定位：情报库的最终产物不是"一条条信号"，而是**画像**——根据解说内容，
把每个对象沉淀为可查询、可验证、可更新的结构化画像。
画像回答："这支队伍/这个选手是什么风格？现在状态如何？领先稳不稳、落后能不能翻？"

### 11.1 三层画像结构

```text
联赛层（league）：联赛信誉度（假赛风险）、形态气候、整体风格倾向。
战队层（team）：风格/打法、近期状态、经济状态、翻盘画像、BP/阵容、熟练度、风险、信任等级。
选手层（player）：位置、风格、英雄池/熟练度、近期状态、关键解说评价、信任等级。
横切维度：经济状态（局内经济差表现）、时间维度（赛前/赛中/赛后）。
```

### 11.2 战队画像字段（核心）

| 字段 | 说明 | 信号标签来源 | 时效 |
| --- | --- | --- | --- |
| identity | 联赛 / 队伍 / 地区 | 页面元数据 | 固定 |
| style 风格/打法 | 核心位（上单/打野/下路）、节奏来源、擅长体系 | style | durable |
| form 近期状态 | 连胜连败、状态趋势、赛程密度 | form | short_lived（1-2 周） |
| economy 经济状态 | 经济领先/落后时的表现（领先稳不稳、落后能否翻盘） | tempo + form | durable |
| proficiency 熟练度 | 英雄池、特定英雄熟练度（解说评价） | proficiency | durable |
| bp BP/阵容 | 常用体系、BP 风格、版本英雄 | bp | durable |
| comeback 翻盘画像 | 翻盘率、被翻盘率、落后反弹力（与客观盘口交叉） | tempo + 验证 | durable |
| risk 风险 | 假赛观察、心态、纪律问题 | event | 持续更新 |
| evidence 证据 | 信号 ID 列表、信任等级（高/中/低）、更新时间 | 全部 | 持续更新 |

选手画像字段（精简版）：身份（队伍/位置）、风格、英雄池/熟练度、状态、
关键评价（quote + 信号 ID）、信任等级。

联赛画像字段：信誉度（假赛风险等级）、形态气候（反转日/崩塌日）、风格倾向、
样本量（队伍级画像 >=10 场才出结论）。

### 11.3 经济状态维度说明

```text
"经济状态"= 局内经济（经济差）表现，不是竞技状态：
  解说常说"落后七千翻盘"（957 评 DK vs HLE）、"经济领先一万被翻"（BLG 大优被翻样本）。
  画像记录该队在领先 / 落后时的表现与阈值（领先多少稳、落后多少还能翻），
  与 Polymarket 价格路径交叉验证（后续做，当前先纯解说沉淀）。
  竞技状态（连胜连败）独立为 form 字段，两者不混。
```

### 11.4 信号 -> 画像的沉淀路径

```text
直播录像（957 等，6-9h/场）
  -> 分段转录（docs/data/transcripts/957/）
  -> 信号提取（record_intel_signal.py -> intel_signals.json）
  -> 赛后验证（verify：应验/部分应验/未应验）
  -> 按"对象 x 标签"聚合 -> 画像字段（team/player/league 画像）
  -> 预期情形（EXPECTATION_VERIFICATION）-> 情报卡 / D5 边际信息
画像更新规则：
  durable 信号 -> 长期画像（style / bp / proficiency / economy / comeback）
  short_lived 信号 -> 近期状态（form），1-2 周后自动降权
  每条画像字段带证据信号 ID；信任等级：高=多笔实锤应验 / 中=单笔实锤+观察 /
  低=观察待验证；预期落空回画像库自校正（信任降级）。
```

### 11.5 与现有资产衔接

```text
输入层：intel_signals.json（信号）+ STREAMER_PROFILES.md（信源）+ 转录文本。
验证层：EXPECTATION_VERIFICATION.md（预期情形盘中验证）+ intel_stats.py（可信度统计）。
画像层：TEAM_PROFILES.md（现有人读视图，升级为画像库）+ 新建 team/player/league 画像 JSON。
应用层：TASK6 情报卡（对外只展示结论性画像与统计，不展示逐笔明细）。
```
