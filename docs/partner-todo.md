# 需要数据合作伙伴完成的事项

> 分工原则：本库先把"情报加工与展示"跑通；朋友的数据接入后把"样本量"做厚。
> 采集规格、队伍清单与避坑详见 [data-guide.md](data-guide.md)。

## 一、全量历史数据抓取与清洗（最高优先）

```text
范围：LPL / LCK / LCK CL / LEC / CS2（IEM / BLAST / EWC）/ Dota2（TI / ESL One）。
时间：近 2-3 个月起步，目标累计 200+ 场。
市场：Game Winner（小局）+ Match Winner / Moneyline（整场）都要；BO3 第三局起只有 Moneyline。
粒度：优先 1 分钟（高成交量市场）；低成交量接受 5-10 分钟并标注。
结算：100c = 胜 / 0c = 负；必须复核最终结算（曾出现互补报价冲突的异常样本）。
```

## 二、历史数据回测策略开发

```text
用全量历史回测：中位80 / S1 / S2 / 让一追二 / 四阶段窗口。
产出：回测报告（胜率 / 盈亏比 / 止损率 / 样本量），对齐本库策略口径。
```

## 三、外部局内事件数据

```text
阵容 / BP / 击杀时间线 / 资源事件（候选源：官方赛事 API / Leaguepedia / PandaScore）。
用途：赛前档案卡的"预期情形"与翻盘案例三阶段的局内事件层。
```

## 四、产品化工程（对外发布门禁）

```text
数据库与后端 API、订阅与支付、海外部署。
门禁：联赛级统计 >=20 样本、队伍级画像 >=10 样本才对外展示。
```

## 五、弹幕 / 解说采集规模化

```text
虎牙回放批量下载、转录、弹幕接口（工具已有一版，规模化可外部承接）。
注意：对外只提供聚合结论，不裸展示弹幕流与用户身份。
```

## 交付格式（对齐本库）

```text
1. 每场 JSONL：价格时间序列（时间戳 + 价格）+ 结算结果 + 元信息（slugs / 队伍 / BO / 小局）。
2. 汇总索引：比赛 -> 市场 -> 文件路径。
3. 标注粒度（1m / 5m / 10m）与数据质量（高 / 中 / 低）。
```
