# 规律探索层与策略构建层

最后更新：2026-08-08

## 0. 第一原则（2026-08-08，全项目方法论）

```text
1. 现象层第一：一切策略、执行、情报都从"市场正在发生什么"出发。
2. 未知优先（防过拟合）：形态识别只输出"已知 / 未知"，
   无法匹配的走势进入观察池（L0），禁止硬套已知形态。
3. 每条新规律必须走：观察池（>=3 个相似图形）-> 登记候选形态 -> 回测验证 -> 入形态库。
4. 已知形态的每个新样本继续积累频率（形态气候），频率本身是信号。
5. 形态不是策略：同一种形态正例是机会、反例是陷阱；
   决定能不能做的是路由策略 + 仓位 + 保护。
```

## 1. 为什么要重分层

之前把 A/B/C/D/E 都放在同一层，容易混乱。

更清晰的方式是：

```text
先发现市场现象。
再判断这个现象是否能构建交易策略。
再对交易策略做回测、模拟和小额实测。
确认稳定后，才进入自动化交易。
```

所以后续项目分为两层：

```text
第一层：规律探索层
第二层：策略构建层
```

另外还有一类：

```text
执行管理模块
```

执行管理模块不是入场策略，负责资金、挂单、止盈、锁盈、关闭订单、复盘。

## 2. 第一层：规律探索层

规律探索层只回答一个问题：

```text
市场正在出现什么现象？
```

它不直接决定下单。

第一版现象库：

```text
P1_LOW_PRICE_PANIC
低价恐慌 / 深度折价：
目标方跌到 10c-35c，但市场仍有波动和修复可能。

P2_FAVORITE_DIP
热门方临时回撤：
赛前或早段热门方从高位跌到 40c-75c，尚未确认彻底失控。

P3_MID_RANGE_TANGLE
中位纠缠：
双方在 35c-65c 之间反复穿越 50%，波动频繁，适合网格观察。

P4_DOMINANT_PULLBACK
强势方小回撤：
优势方大部分时间处于 70c-90c，只在短时事件中回撤。

P5_BO_SERIES_COMEBACK
BO3/BO5 整场反转：
Match / Series Winner 中，首局失利或前半段落后导致整场赔率折价，但仍有系列赛修复空间。

P6_POSITION_RISK
已有持仓风险：
用户已有仓位，浮亏、浮盈回吐、卖单不足或彩票仓过大。
```

说明：

```text
原来的 E_BO3_SERIES_COMEBACK 应归入 P5。
它是现象标签，不是交易策略。
```

## 3. 第二层：策略构建层

策略构建层回答三个问题：

```text
这个现象能不能交易？
应该怎么买？
应该怎么卖和控风险？
```

当前策略库：

```text
S1_REVERSAL_GRID
低价反转网格：
主要来自 P1，也可以叠加 P3 / P5。
对应旧 A。

S2_FAVORITE_DIP_GRID
热门回撤网格：
主要来自 P2，也可以叠加 P5。
对应旧 B。

S3_DOMINANT_PULLBACK_GRID
强势小回撤网格：
主要来自 P4。
对应旧 C。

S4_POSITION_MANAGEMENT
持仓管理 / 降风险：
主要来自 P6，也可以结合任何市场现象。
对应旧 D。
```

旧命名映射：

```text
A -> S1_REVERSAL_GRID
B -> S2_FAVORITE_DIP_GRID
C -> S3_DOMINANT_PULLBACK_GRID
D -> S4_POSITION_MANAGEMENT
E -> P5_BO_SERIES_COMEBACK
D2 -> 执行管理模块，不是策略
P  -> 执行节奏模块，不是策略
```

## 4. 执行管理模块

执行管理模块不负责判断“这个机会好不好”。

它负责：

```text
固定金额预算
买入档位
成交后立即挂卖单
自动锁盈
彩票仓上限
关闭订单
平仓
状态摘要
复盘记录
```

当前执行模块：

```text
M1_FIXED_BUDGET
固定金额制。

M2_GRID_ENTRY
分档买入。

M3_TAKE_PROFIT
成交后自动挂止盈。

M4_D2_PROFIT_LOCK
浮盈保护 / 自动锁盈。

M5_LOTTERY_CAP
彩票仓成本上限。

M6_ORDER_CLOSE
关闭未成交订单。

M7_REVIEW_LOOP
交易后复盘，回流到规律探索层。
```

## 5. 从现象到自动化的流程

每一个新发现都按这个路径推进：

```text
1. 现象记录
   只描述市场发生了什么，不急着下结论。

2. 规律假设
   判断这种现象是否重复出现，是否有可交易窗口。

3. 策略草案
   设计买入区间、卖出区间、资金、彩票仓和不交易条件。

4. 回测验证
   用历史价格验证固定金额网格是否合理。

5. 模拟 / 建议
   先不实盘，只输出建议和计划。

6. 小额实测
   固定小金额执行，必须复盘。

7. 自动化交易
   只有稳定后，才进入自动化执行。
```

## 6. 产品展示方式

候选机会里应该分开显示：

```text
市场现象：
P1 / P2 / P3 / P4 / P5 / P6

建议策略：
S1 / S2 / S3 / S4

执行模块：
M1 / M2 / M3 / M4 / M5

当前成熟度：
观察 / 回测 / 模拟 / 小额实测 / 自动化
```

示例：

```text
现象：P5_BO_SERIES_COMEBACK + P2_FAVORITE_DIP
策略：S2_FAVORITE_DIP_GRID
执行：固定金额 + 分档买入 + 自动止盈 + D2锁盈
状态：小额实测
```

这样就不会把“BO3 整场反转”误当成一个独立交易策略。

## 7. 当前任务 2 的正确边界

任务 2 不是直接自动交易，也不是只找 E 型。

任务 2 要做的是：

```text
按时间扫描白名单赛事。
识别市场现象标签。
判断是否能路由到已有策略 S1 / S2。
输出候选机会排序。
不触发实盘下单。
```

第一版先稳定：

```text
P1 -> S1
P2 -> S2
P5 + P1 -> S1
P5 + P2 -> S2
```

P3 / P4 / P6 继续记录和少量验证，不急着全自动。
